# Инструкция для ИИ-агента: как сделать документацию совместимой с OnePageDocs

> Для людей: дай агенту эту строку —
> «Сделай документацию в этом репозитории совместимой с OnePageDocs по инструкции https://github.com/VadimCat/OnePageDocs/blob/main/docs/AI_DOCS_SETUP.md и прогони проверку».

Ты агент, который работает с Markdown-документацией. OnePageDocs — это одностраничное браузерное приложение. Оно показывает все `.md` файлы папки одной лентой и сохраняет правки прямо в эти файлы. Твоя задача — подготовить репозиторий так, чтобы документы корректно отображались, ссылки работали, а сохранение не портило файлы. **Не меняй смысл документов.** Меняется только оформление, имена файлов и ссылки, и только там, где это нужно для совместимости.

## 1. Что умеет инструмент (это твои ограничения)

| Возможность | Поддержка |
|---|---|
| Markdown | CommonMark + GFM: таблицы, `- [ ]` чекбоксы, зачёркивание, автоссылки, fenced code |
| Свойства (front matter) | YAML **только плоский**: `key: value`, списки `- item` или `[a, b]`, строки в кавычках. Вложенные ключи и многострочные `|` / `>` показываются неправильно |
| Wiki-ссылки | `[[Имя]]`, `[[Имя#Заголовок]]`, `[[Имя|подпись]]`, `[[#Заголовок]]`. Цель ищется **по имени файла без расширения во всей папке** |
| Обычные ссылки | Относительные `[текст](../Папка/Файл%20с%20пробелами.md#раздел)` |
| Якоря | Заголовки `#`–`######`. Фрагмент сравнивается с текстом заголовка (точно, по slug или по началу) |
| Чекбоксы | Клик в просмотре меняет `[ ]`↔`[x]` прямо в строке файла. Строки внутри ``` не трогаются |
| Картинки | Относительные пути к файлам внутри выбранной папки |
| Встраивания `![[...]]`, `.canvas`, `.base` | Не рендерятся: показывается плашка. Сами файлы не трогаются |
| Кодировка | Только UTF-8. BOM и стиль переводов строк (CRLF/LF) сохраняются при записи |
| HTML внутри Markdown | Рендерится как есть, скрипты не выполняются. Не полагайся на него |

## 2. Правила для документов

1. **Уникальные имена файлов.** `[[Имя]]` открывает первый найденный файл с таким именем. Два `README.md` или два `Plan.md` в разных папках — источник ошибок. Переименуй файлы (`Plan` → `Plan Combat`) или ссылайся путём: `[[Systems/Plan]]`.
2. **Плоский front matter.** Одна строка — одно свойство. Списки — через `- ` с отступом или `[a, b]`. Ссылки в свойствах пиши в кавычках: `- '[[S01 Кооператив]]'`. Вложенные объекты вынеси в тело документа (таблица или список).
3. **Заголовки как якоря.** Если на раздел ссылаются (`[[Doc#Q02]]`), у этого раздела должен быть свой заголовок с этим текстом. Не дублируй одинаковые заголовки внутри одного файла, если на них ссылаются.
4. **Чекбоксы — только для настоящих пунктов.** Формат строго `- [ ] текст` или `- [x] текст` (также `*`, `+`, `1.`). Пример чекбокса в документации помещай в блок ```.
5. **Генерируемые файлы помечай.** Если файл пересобирается скриптом, добавь в front matter `generated: true` или фразу-маркер в текст и пропиши её в `generatedMarker` конфига. Редактор покажет предупреждение, что ручные правки затрутся.
6. **UTF-8.** Не сохраняй файлы в cp1251, UTF-16 и т. п. Смешанные CRLF/LF внутри одного файла нормализуй.
7. **Не клади в docs огромные файлы.** Логи, выгрузки и дампы на сотни килобайт держи вне `docsRoot` или добавь их папку в `skip`.
8. **Имена папок первого уровня = группы в оглавлении.** Документ в корне `docsRoot` попадает в первую группу, в `docsRoot/Systems/...` — в группу «Systems». Глубже вложенность не создаёт новых групп.

## 3. Конфиг `onepage-docs.json`

Создай его **в корне репозитория** (в той папке, которую пользователь выбирает в редакторе). Все поля необязательны. Схема лежит в `onepage-docs.schema.json`.

```json
{
  "$schema": "https://vadimcat.github.io/OnePageDocs/onepage-docs.schema.json",
  "title": "Project name",
  "subtitle": "GDD",
  "language": "ru",
  "docsRoot": "docs",
  "includeOutside": true,
  "groups": [
    { "path": "", "label": "Главное" },
    { "path": "Systems", "label": "Системы" },
    { "path": "Templates", "label": "Шаблоны", "hidden": true }
  ],
  "pin": ["00 Старт", "Концепт"],
  "last": ["INDEX"],
  "skip": ["Deliverables", "Archive"],
  "generatedMarker": ["Генерируется валидатором"],
  "hideProps": ["project"],
  "propLabels": { "depends_on": "зависит от", "status": "статус" },
  "status": {
    "bad":  ["^не ", "^blocked"],
    "warn": ["частич", "^draft"],
    "ok":   ["^готов", "^done"]
  }
}
```

| Поле | Значение |
|---|---|
| `title`, `subtitle` | Шапка и заголовок вкладки. По умолчанию — имя папки |
| `language` | `ru` или `en` для интерфейса. По умолчанию — язык браузера |
| `docsRoot` | Папка с документацией относительно корня. `"auto"` (по умолчанию) = `docs`, если она есть, иначе корень |
| `includeOutside` | Показывать ли `.md` вне `docsRoot` (README, AGENTS) отдельной последней группой. По умолчанию `true` |
| `groups` | Порядок и подписи групп. `path` — имя папки первого уровня внутри `docsRoot`, `""` — файлы в корне. `hidden: true` — группа скрыта, пока пользователь её не откроет |
| `pin` / `last` | Имена файлов (без `.md`) или пути, которые идут первыми / последними в своей группе. По умолчанию первыми идут файлы на `00 ` и `README` |
| `skip` | Имена папок, которые не сканируются (в дополнение к `node_modules`, `Library`, `Temp`, `obj`, `bin`, `dist`, `worktrees` и скрытым папкам) |
| `generatedMarker` | Строки; файл, содержащий любую из них, помечается «генерируется» |
| `hideProps`, `propLabels` | Скрыть свойства front matter / переименовать их в шапке документа |
| `status` | Регулярные выражения (без учёта регистра) для раскраски значений свойств: `bad` красный, `warn` жёлтый, `ok` зелёный. Проверяются в этом порядке |
| `maxFiles` | Предел числа файлов, по умолчанию 1500 |

## 4. Порядок работы

1. Найди, где лежит документация, и запусти проверку (Node 18+):
   ```bash
   curl -sL https://raw.githubusercontent.com/VadimCat/OnePageDocs/main/tools/check.mjs | node - <путь-к-репозиторию>
   # или из клона OnePageDocs:
   node tools/check.mjs <путь-к-репозиторию>        # --json для машинного вывода
   ```
2. Создай `onepage-docs.json` по разделу 3: группы — по фактическим папкам, подписи — на языке документации, генерируемые файлы — в `generatedMarker`, служебные папки — в `skip`.
3. Исправь **ошибки** проверки (`ERROR`): невалидный UTF-8, незакрытый front matter, битый конфиг. Без этого сохранение испортит файлы.
4. Разбери **предупреждения** (`WARN`):
   - дубли имён — переименуй файл и обнови все ссылки на него (поиск по `[[Старое имя` и по пути);
   - ссылки на несуществующие документы и заголовки — исправь цель, если она очевидна; иначе оставь и перечисли пользователю;
   - ссылки на `.canvas` / `.base` / картинки, которых нет, — то же самое;
   - вложенный front matter — согласуй с пользователем, прежде чем менять схему свойств: от неё могут зависеть скрипты и Obsidian Bases.
5. Если в репозитории есть свои валидаторы или генераторы индекса, запусти их после правок: совместимость не должна ломать существующий процесс.
6. Добавь в `AGENTS.md` / `CLAUDE.md` проекта короткий пункт: «Документация открывается в OnePageDocs. Держать имена файлов уникальными, front matter плоским, кодировку UTF-8; после правок запускать проверку OnePageDocs».
7. Повтори проверку до `0 error(s)`. Сообщи пользователю: что изменено, что осталось предупреждением и почему.

## 5. Чего не делать

- Не переписывай содержание и не «улучшай» формулировки ради совместимости.
- Не удаляй `.canvas`, `.base` и другие файлы Obsidian: редактор их просто не показывает.
- Не конвертируй wiki-ссылки в обычные и наоборот без просьбы: поддерживаются оба вида.
- Не переименовывай файлы, на которые ссылаются извне (CI, скрипты, `registry.json`), не обновив эти ссылки.
- Не коммить `onepage-docs.json` с абсолютными путями: все пути относительные.
